同じ 1Mトークンを出力しても、メインセッションと recorder では単価が約42倍違う。 どの担当にどのモデルを置くかで、同じ作業量でも支払いが変わる。

割り当ての考え方

太字はどれも元図にある割り当て。そのあとの理由は自分の解釈になる。

  • 上ほど高いモデル、下ほど安いモデルを置く。 探す・記録するだけの担当に最上位モデルは要らない
  • search には low、recorder には minimal を当てる。 search は決まった場所を見に行き、recorder は決まった形式で書き出すので、effort を下げている
  • worker には director と同じ中間のモデルを当てる。 レポート本文を作るので、low まで下げてよいかは未検証
  • メインセッションには実作業を持たせない。 判断と指示出しに絞ると、最上位モデルの出力トークン量が減る
